# Katya — бизнес-план

Дополняет [CONCEPT.md](CONCEPT.md) (продукт и UX) и [DESIGN.md](DESIGN.md) (интерфейс). Здесь — на чём и как зарабатывает
инструмент.

## 1. Что продаём одной фразой

**Швейцарский нож для действий в вебе.** Любое действие на любой странице — клик, ввод, скачивание, проверка, скриншот —
становится воспроизводимым шагом, который можно записать рукой, запустить по расписанию, вызвать по API или отдать
ИИ-агенту. Платят не за «браузер», а за надёжно выполненное действие и за время, которое оно экономит.

История-ориентир: когда-то на Shutterstock покупка картинки была цепочкой ручных кликов; потом появился API, и действие
«купить и скачать» стало одной операцией, за которую готовы платить, потому что она встроена в чужой процесс. Katya делает
то же для сайтов, у которых API нет или он неполный: действие «как человек» превращается в операцию с результатом.

## 2. Лезвия ножа

| Лезвие | Что делает | Кому | Чем монетизируется |
|---|---|---|---|
| **Запись и повтор** | записал на кадре → сценарий → повтор N раз, с выбранного шага | авторы, малый бизнес, операторы | бесплатно: воронка |
| **Расписания** | сценарий сам запускается по cron, результат с скриншотом | все, кто делает рутину «каждый день в 9:00» | Pro |
| **Триггеры** | «когда видно X → сделать Y», проверка на живой странице | операторы, поддержка, QA | Pro |
| **Руки для агента (MCP)** | Claude/Codex/OpenClaw открывают вкладки, смотрят, кликают, читают | разработчики агентов | Agents: по использованию |
| **Мой Chrome** | сценарий в твоём залогиненном Chrome через расширение | личные кабинеты без API | Pro |
| **История и уведомления** | журнал запусков, скриншот сбоя, Telegram/Discord | команды | Pro / Team |
| **CLI и файлы сценариев** | `katya run scenario.json` в CI, на сервере, в скриптах | интеграторы | Team / Agents |
| **Файловый выход** | скриншоты, загрузки, текст страниц → файлы и API | все | входит везде |

Граница ножа: не режем правила площадок. Не обходим капчи и антибот, не имитируем людей для метрик, не трогаем вход
Google автоматикой. Это не моральная оговорка, а условие выживания продукта и его продаваемости бизнесу.

## 3. Модель монетизации

**Open-core + использование.**

| Уровень | Цена | Включает | Ограничение бесплатного |
|---|---|---|---|
| Free | 0 | панель, запись, сценарии, триггеры (до 5), MCP локально, Docker | 1 устройство, без расписаний и истории |
| Pro | 9 $/мес или 79 $/год | расписания, история 90 дней со скриншотами, уведомления, переменные-секреты, «Мой Chrome», синхронизация сценариев | 1 человек, до 3 устройств |
| Team | 29 $/мес за 5 мест | общая библиотека, роли, несколько раннеров в одной панели, аудит, SSO позже | +5 $ за место |
| Agents | кредиты: 1 кредит = 1 минута браузера, от 5 $ за 1 000 | хостед-раннеры по API, лимиты, журнал | бесплатно 100 кредитов в месяц |

Дополнительные потоки:

- **Библиотека сценариев**: шаблоны под популярные площадки (кабинеты рекламы, маркетплейсы, CRM). Платные шаблоны 3–15 $,
  автору 70 %. Это также бесплатный канал привлечения: авторы приводят аудиторию.
- **Внедрение**: настройка 5–10 сценариев под бизнес, 300–1 500 $ разово. Первые 10 клиентов — руками, чтобы понять спрос.
- **Белая этикетка** (позже): ядро под брендом партнёра-интегратора.

Почему именно так: бесплатное ядро даёт установки и упоминания в каталогах MCP; платят за то, что работает без человека
(расписания, история, уведомления) и за масштаб (команды, кредиты).

## 4. Юнит-экономика на салфетке

- Себестоимость Pro ≈ 0: всё выполняется на устройстве пользователя; наши расходы — синхронизация и уведомления (центы).
- Хостед-раннер: минута Chromium на VPS ≈ 0,002–0,004 $; продаём за 0,005 $ (1 000 кредитов за 5 $) → маржа 30–60 %.
- Цель первого года: 300 Pro + 20 Team ≈ 3 300 $/мес регулярного дохода + внедрения. Этого достаточно, чтобы продукт
  окупал один-два человеко-месяца разработки в месяц.

## 5. Выход на рынок

1. **Своя рутина как витрина.** Канал Techno Punch: 10 сценариев для контент-операций (анонсы в соцсети, обновление
   описаний, выгрузка статистики через официальные кабинеты, заполнение форм площадок). Каждый — короткое видео «записал за
   минуту, работает само». Это контент для канала и демо продукта одновременно.
2. **Каталоги агентов.** Публикация MCP-сервера в реестрах (Smithery, MCP-каталоги Claude/Cursor). Разработчики агентов —
   самый тёплый сегмент: им нужны «руки» уже сегодня.
3. **Открытый код на GitHub** с понятным README и одной командой запуска под Windows и Docker. Issue-трекер как канал
   обратной связи.
4. **Сообщество авторов сценариев**: шаблоны, обмен, рейтинг. Начать с Telegram-чата.

## 6. План на 90 дней

| Недели | Что | Результат |
|---|---|---|
| 1–2 | Стабилизация ядра, расписания, история, уведомления, CLI (идут параллельно) | можно пользоваться каждый день без панели |
| 3–4 | 10 собственных сценариев, видео-демо, README на английском | витрина и первые внешние пользователи |
| 5–6 | React-интерфейс по CONCEPT.md, универсальные компоненты для всех экранов | продуктовый вид |
| 7–8 | Аккаунт, синхронизация сценариев, оплата (Stripe/Paddle), Pro-переключатель | первая оплата |
| 9–10 | MCP в каталогах, кредиты для хостед-раннера на одном VPS | сегмент агентов |
| 11–12 | Библиотека шаблонов, 5 платных внедрений | подтверждение спроса |

## 7. Метрики

- Еженедельно активных устройств; доля с хотя бы одним расписанием (конверсия в Pro-ценность).
- Запусков без участия человека в неделю; доля успешных.
- Время до первого сохранённого сценария у нового пользователя (цель < 3 минут).
- Действий агентов через MCP в неделю.
- Платящих / активных; отток Pro по месяцам.

## 8. Риски и ответы

| Риск | Ответ |
|---|---|
| Площадки меняют вёрстку, сценарии ломаются | устойчивые селекторы (роль, текст, подпись), история со скриншотом сбоя, быстрая перезапись шага с места сбоя |
| Площадки блокируют автоматизацию | работаем в рамках правил и официальных кабинетов, «Мой Chrome» для личных кабинетов, никаких обходов |
| Конкуренты (Browserbase, Playwright MCP, no-code RPA) | наш фокус — запись рукой + агенты + локальность; дешевле RPA, проще Playwright, не требует облака |
| Один разработчик | открытый код, агенты в разработке (Claude, Codex), приоритет простым, законченным функциям |
| Приватность данных | всё локально, токены свои, пароли не записываются и не хранятся |
