# Katya — концепция продукта

Документ для основателя и для всех, кто пишет код (люди, Claude, Codex). Что мы делаем, для кого, как это зарабатывает и как
должен быть устроен интерфейс. Правила визуального языка — в `DESIGN.md`; здесь — зачем и что.

## 1. Одной фразой

**Katya — руки для браузера.** Человек или ИИ-агент записывает действия на живой странице, сохраняет их как сценарий и
запускает где угодно: на своём Windows-ПК, на домашнем mini-PC, на сервере. Один сценарий — один файл, одна кнопка.

Что Katya не делает: не притворяется человеком перед сервисами, не накручивает метрики, не обходит защиту аккаунтов.
Это принципиально: продукт, построенный на обходе правил, живёт до первого бана и не продаётся.

## 2. Для кого

| Сегмент | Боль | Что даёт Katya |
|---|---|---|
| **Создатель контента / малый бизнес** (ты сам: Techno Punch) | Десятки одинаковых действий в вебе каждую неделю: публикации, карточки, формы, выгрузки | Записал один раз → запускаешь по расписанию, с переменными |
| **Разработчик, работающий с ИИ-агентами** (Claude Code, Codex, OpenClaw, Cursor) | Агенту нужен браузер с состоянием, которым можно управлять шагами и видеть результат | MCP-сервер: открыть вкладку, посмотреть, кликнуть, прочитать, снять скриншот, запустить сценарий |
| **Оператор, QA, поддержка** | Проверить, что сайт живой и форма работает, на нескольких профилях браузера | Триггеры и сценарии с проверкой на открытой вкладке, скриншоты в файлы, отчёт |
| **Команды с самохостингом** | Не хотят отдавать cookies и данные облачному сервису | Docker на ARM/x86, всё локально, ключ API свой |

Первый сегмент — ты. Продукт обязан решать твои задачи вокруг канала честно: кросспостинг анонсов, обновление описаний,
сбор статистики через официальные интерфейсы, заполнение форм площадок, рассылки. Это то, что можно показать и продать другим
авторам.

## 3. Бизнес-модель

**Open-core.** Ядро открыто и бесплатно — это рост, доверие и вклад агентных экосистем (MCP). Деньги — за удобство и
масштаб.

| Уровень | Для кого | Что входит | Цена-ориентир |
|---|---|---|---|
| **Katya Free** | один человек, один ПК | панель, запись, сценарии, триггеры, MCP, Docker | 0 |
| **Katya Pro** | автор / фрилансер | расписания, переменные с секретами, уведомления о сбоях, история запусков со скриншотами, синхронизация сценариев между устройствами | ~9 $/мес |
| **Katya Team** | небольшая команда | общая библиотека сценариев, роли, несколько раннеров (ПК + mini-PC + сервер) из одной панели, аудит | ~29 $/мес за 5 мест |
| **Katya Agents** | разработчики агентов | хостед-раннеры по API, квоты минут браузера, готовые MCP-профили | по использованию |

Дополнительно: **библиотека сценариев** (шаблоны для популярных площадок, часть платные, авторы получают долю) и
**внедрение под ключ** для малого бизнеса.

Что не продаём никогда: «просмотры», «подписчиков», «обход капчи», «невидимый браузер». Отказ от этого — часть бренда.

## 4. Концепция интерфейса: три режима, один экран

Сейчас панель — набор карточек, появившихся по мере разработки. Новая структура исходит из того, что человек делает:

```
┌ Левая рейка ──────┬ Рабочая область ─────────────────────────┬ Инспектор ───────────┐
│ ▣ Вкладки         │  Превью вкладок (живые, кликабельные)      │ Сценарий этой вкладки│
│ ▶ Сценарии        │  Сетка 1–4 превью, одно можно развернуть   │ транспорт: ● ▶ ■ ⟲ n │
│ ⚡ Триггеры        │                                            │ шаги · прогресс      │
│ ▤ Файлы           │                                            │ элемент под курсором │
│ ⚙ Агенты / API    │                                            │ настройки запуска    │
└───────────────────┴────────────────────────────────────────────┴──────────────────────┘
```

**Три режима работы с вкладкой**, переключаются одной кнопкой в инспекторе:

1. **Смотреть** — живое превью, клики, прокрутка, ввод с клавиатуры. Ничего не записывается.
2. **Записать** — то же самое, но каждое действие ложится в сценарий. Красная рамка превью, счётчик шагов,
   «транспорт» как в DAW: запись, стоп, воспроизведение, повтор N раз. Это и есть «кнопка записи, объединённая с панелью
   сценария», которую ты просил.
3. **Запустить** — выбран сценарий, видно текущий шаг, можно кликнуть по шагу и продолжить с него, остановить, повторить.

**Инспектор элемента вместо «ручного действия по селектору».** Навёл курсор на превью — справа показано, что это за элемент
(кнопка «Продолжить», поле «Email»), и три кнопки: Клик · Ввести · Ждать появления. Селектор подбирается сам
(текст → роль → подпись → CSS), сырые селекты скрыты за «Точнее».

**Триггеры живут рядом с вкладкой.** Форма «когда видно X → сделать Y» с кнопками «Проверить на вкладке» и
«Выполнить сейчас» (уже сделано), плюс журнал срабатываний на карточке вкладки.

**Сценарий = один объект.** Шаги, переменные, стартовый адрес, заголовки, профиль браузера, расписание — всё в одном месте,
одинаково в панели и на странице сценариев. Экспорт/импорт JSON, отправка в библиотеку.

**Агенты — равноправные пользователи.** Раздел «Агенты / API»: ключ, список подключённых MCP-клиентов, их последние
действия, лимиты. Любое действие агента видно в журнале как действие человека.

## 5. Что убрать

- Баннер «время воспроизведения видео» и подсчёт часов: это не продукт, а наследие. Оставить как опциональную метрику
  в инспекторе для страниц с видео.
- «Быстрые ссылки ♡» — не функция продукта.
- Дублирование: «Копировать шаги», «Загрузить запись», «Сохранить сценарий» — уже сведены к транспорту и меню «⋯»; то же
  сделать на странице сценариев.

## 6. Дорожная карта

**Фаза 1 — опора (сейчас).** Панель стабильна: запись, сценарии с настройками, триггеры с проверкой, MCP, Windows-запуск,
Docker. Цель — ежедневно использовать для задач канала и записать 10 реальных сценариев. Это даёт понимание, чего не
хватает, лучше любых гипотез.

**Фаза 2 — продуктовый UI.** Переезд на Vite + React + TypeScript по схеме из раздела 4 (карточка-задача уже есть).
Инспектор элемента, транспорт, журнал. Один дизайн-язык (`katya.css`, эффекты как опция).

**Фаза 3 — Pro.** Расписания, история запусков со скриншотами, уведомления (Telegram/Discord), секреты в переменных,
синхронизация сценариев через аккаунт. Первая оплата.

**Фаза 4 — Team и Agents.** Несколько раннеров в одной панели, роли, хостед-раннеры по API, библиотека сценариев.

## 7. Метрики, по которым поймём, что получается

- Сколько сценариев запускается без участия человека в неделю (главная).
- Доля сценариев, доживших до 10 запусков (качество записи и устойчивость селекторов).
- Время от «открыл вкладку» до «сохранил первый сценарий» у нового пользователя (цель — меньше 3 минут).
- Число действий, сделанных агентами через MCP.
